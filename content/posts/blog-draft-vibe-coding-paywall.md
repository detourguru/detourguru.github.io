요즘 바이브코딩으로 결제까지 붙여 운영하는 서비스가 심심찮게 보인다. 바이브코딩으로 만든 지는 어떻게 알았냐고 하면 답하기 좀 애매하긴 하지만 미묘하게 AI로 만든 티가 난다고 해야 할까? 아무튼 얼마 전 공유 링크를 타고 들어갔던 한 콘텐츠 페이지도 그렇게 만든 것 같은 서비스였다.

페이지에서는 콘텐츠의 결과물 앞부분만 미리보기로 보여주고 전체 내용을 보거나 원본 파일을 받으려면 결제해야 한다고 안내하고 있었다 (참고로 그리 싸지 않은 가격이었다). 그런데 아마 개발자들은 약간 공감할 수도 있는데, 문득 궁금증이 들어서 습관처럼 개발자 도구를 열어 네트워크 탭을 확인해보니 응답에 결제해야 볼 수 있다던 전체 내용과 원본 파일 주소가 그대로 들어 있었다! 화면에서만 가려져 있었을 뿐이고 이미 모든 데이터는 브라우저 상에 존재하고 있는 상태였다.

## 결제 여부는 데이터가 아닌 화면만을 가리고 있었다

결제 안 한 사용자가 받은 응답에 전체 내용이 들어 있었다는 건 서버가 결제 여부와 상관없이 같은 데이터를 내려줬다는 뜻이다. 결제했는지는 그 데이터를 받은 화면이 그릴 때 확인하고 있었다.

서비스 코드는 볼 수 없었지만 아래는 비슷한 구조로 만들어본 예시 코드다. 서버는 콘텐츠를 통째로 내려주고, 화면은 `isPaid` 값을 보고 전체를 그릴지 앞부분만 잘라 그릴지 정한다.

```tsx
// 서버는 결제 여부와 상관없이 { title, body, fileUrl }을 전부 내려준다
const { data } = useQuery({
  queryKey: ['content', id],
  queryFn: () => fetchContent(id),
});

if (!data) return null;

return isPaid ? (
  <FullView body={data.body} fileUrl={data.fileUrl} />
) : (
  <PreviewView body={data.body.slice(0, 200)} /> // 화면에서만 자른다
);
```

결제 안 한 사용자는 `PreviewView`만 보게 되니 화면만 보면 잘 막혀 있다. 그런데 `slice`로 자르기 전의 `data.body`는 이미 브라우저 메모리에 있고, 그 값이 담긴 응답은 네트워크 탭에 그대로 남는다. `fileUrl`도 다운로드 버튼만 안 그렸을 뿐 주소는 응답에 들어 있다. 막은 곳은 그리는 단계였고 받는 단계에는 아무 조건이 없었던 것이 문제였다.

## AI에게 요청할 땐 원위시윌로우에 소원 빌듯이 하자 (아니면 지니)

그렇다면 AI가 잘못한 것일까? 아마 AI는 시킨 대로 만들었을 거다. 이 기능을 바이브코딩으로 만든다고 해보자. 그러니까 자연어로 요청을 하는 것이다. 아마 `"결제 안 한 사용자한테는 앞부분만 보여주고 나머지는 결제 후 보여준다는 버튼으로 막아줘"` 같은 문장으로 요청하게 될 것 같다. 근데 이 문장에는 어디서 막아야 하는지가 없다. 위 예시처럼 화면에서 잘라도 요청은 그대로 만족한다.

결제 안 한 계정으로 들어갔을 때 앞부분만 보이고 결제 버튼이 뜨면 QA 통과다! 아무래도 코드는 확인하지 않고 화면만 확인하게 될 테니 요청에 충실하게 구현된 기능으로 보였을 것이다.

옵세션이라는 영화에서 주인공은 소원을 딱 하나 들어준다는 장난감 원위시윌로우에 짝사랑하던 친구가 세상 누구보다 자기를 사랑하게 해달라고 빈다. 소원은 정말 말한 `그대로` 이루어지는데, 바로 그게 문제가 돼서 이야기가 끔찍하게 흘러간다. AI에게 뭔가 요청할 때도 비슷하다. 말하지 않은 조건은 채워지지 않을 수 있으니까 원하는 결과를 정확하게 얻으려면 조건을 달아서 요청해야 한다. 예컨대 이런 식이다.

> "결제한 사용자만 전체 내용을 볼 수 있게 해줘. 결제하지 않은 사용자에게는 미리보기 데이터만 보내고, 전체 내용이나 원본 파일 주소는 아예 전달하지 마. **화면에서 숨기는 게 아니라 서버에서 결제 여부를 확인하도록 만들어줘.**"

## ???: 아니 근데 서버에서 결제 여부를 확인했어야 하는지 제가 어떻게 알아요

사실은 맞는 말이다. 모르는 사실에 대해 요청할수는 없는 노릇이다. 그럼 어떻게 해야할까? 이런 실수는 딱 하나만 기억하면 피할 수 있다. 그건 바로 브라우저로 보낸 데이터는 `사용자가 다 볼 수 있다`는 것이다. 

API 응답은 네트워크 탭에 남고, CSS로 흐리게 하거나 `display: none`으로 숨긴 글자는 Elements 탭에 그대로 있다 (혹시 궁금하다면 F12로 개발자 도구를 켜고 왼쪽 상단 화살표 버튼을 눌러 화면 상의 요소를 클릭해보자). 프론트 코드에 직접 박혀있는 값은 내려받은 JS 파일에서 검색하면 나온다. 화면에 안 보인다고 데이터가 없는 게 아니다.

서버에서 렌더링하면 괜찮지 않을까? 아쉽게도 이것도 같다. Next.js App Router에서 서버 컴포넌트가 DB에서 꺼낸 객체를 `"use client"` 컴포넌트에 props로 통째로 넘기면, 그 객체의 필드가 전부 직렬화돼서 HTML과 함께 브라우저로 간다. 화면에는 `title`만 그려도 `body`와 `fileUrl`은 페이지 소스 안에 들어 있는 것이다.

그러니까 이 원칙 하나만 알고 있으면 바이브코딩을 할 때도 AI에게 좀 더 구체적으로 소원을 빌 수있다. 결제나 권한처럼 사람마다 보여줄 게 다른 기능을 만들었다면 다 만들고 나서 AI에게 한번 물어보자. `혹시 결제 안한 사람이 개발자 도구를 열었을때 보일 수도 있나?`

### ???: 그럼 개발자 도구를 못 열게 막으면 되잖아요

아마 이런 시도를 방지하기위해 우클릭이나 개발자 도구를 막아놓은 사이트도 종종있는 것 같다. 그런데 요즘은 역설계를 통해 내부적으로 사용되는 API 주소도 금새 알아낼 수 있다. curl로 요청하면 화면만 없을 뿐 모든 데이터가 포함된 응답이 오게된다.

## 응답을 만들 때 결제 여부를 확인하자

그래서 고쳐야 하는 곳은 화면이 아니라 서버가 응답을 만드는 시점이다. 결제 여부는 서버가 로그인 정보나 뭐 특정 값으로 직접 확인하고, 결제 안 한 사용자의 응답에는 전체 내용 대신 서버에서 잘라둔 미리보기만 넣는다. 아래는 결제 여부에 따라 응답을 만드는 예시 코드다.

```ts
export async function GET(
  _req: Request,
  { params }: { params: Promise<{ id: string }> },
) {
  const { id } = await params;
  const content = await getContent(id);
  if (!content) return Response.json(null, { status: 404 });

  const user = await getCurrentUser(); // 쿠키로 서버가 직접 확인한다
  const purchased = user ? await hasPurchased(user.id, id) : false;

  return Response.json({
    title: content.title,
    preview: content.body.slice(0, 200), // 미리보기는 서버에서 잘라서 보낸다
    body: purchased ? content.body : null, // 안 산 사람에겐 보내지 않는다
    fileUrl: purchased
      ? await createSignedUrl(content.fileKey, 60 * 10) // 10분 뒤 만료되는 주소
      : content.previewFileUrl, // 미리보기용으로 따로 만든 파일
  });
}
```

이렇게 바꾸면 클라이언트는 더 이상 `isPaid`를 들고 고민할 필요가 없다. 응답에 `body`가 있으면 전체를 그리고 없으면 `preview`를 그리면 끝이다.

```tsx
return data.body ? (
  <FullView body={data.body} fileUrl={data.fileUrl} />
) : (
  <PreviewView body={data.preview} />
);
```

서버 컴포넌트에서 데이터를 바로 꺼내 쓰는 구조라면 같은 확인을 클라이언트 컴포넌트에 넘기기 전에 하면 된다. 앞의 Next.js 문서는 이 일을 서버에서만 도는 데이터 접근 함수 한 곳에 모아두고, 그 함수가 권한을 확인한 다음 필요한 필드만 담아서 돌려주게 하라고 권한다.

## 배운점

바이브코딩에 대해 이렇다 저렇다 말이 많지만 나는 비개발자도 아이디어를 바로 프로덕트나 목업으로 만들어볼 수 있는 가장 좋은 도구라고 생각한다. 기술이 없어서 못 만들던 사람이 서비스를 만들고 다른 사람의 니즈까지 파악해서 결제를 붙여 수익을 내는 걸 보면 `와 나는 왜 저런 생각을 못 했지?` 싶어지기도 한다.

그런데 그렇게 좋은 아이디어로 만든 서비스에 이런 구멍이 있으면 너무 아깝다. 이번처럼 결과물을 만들어서 파는 서비스는 그 결과물이 곧 상품인데 개발자 도구 한 번이면 결제 없이 다 보이는 셈이니까. 또 사용자 입장에서도 이런 구멍이 보이면 결제하기가 꺼려진다. 큰 기업들도 데이터 유출 사고가 심심찮게 터지는 마당에 보안 지식 없이 만든 사이트는 또 오죽할까 싶어지기 때문이다.

다행인 건 이 구멍은 원칙 하나만 알면 막을 수 있다는 거다. 화면에서 가린 데이터도 브라우저에는 이미 와 있다는 것. 그러니 결제나 권한이 걸린 기능을 다 만들었다면 결제 안 한 계정으로 개발자 도구를 한 번 열어보고, AI에게도 한 번 물어보자.

결국 AI라는 지니/마법의지팡이/원위시앤윌로우도 빈 소원을 말한 그대로 들어줄 뿐이라, 무엇을 빌어야 하는지는 만드는 사람이 자기가 뭘 원하는지 정확히 알고 있는 것이 가장 중요하다고 생각한다.
