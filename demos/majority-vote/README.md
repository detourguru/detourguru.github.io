# 캐스팅 다수결 데모

같은 캐스팅보드를 LLM에 세 번 읽혔을 때, 한 번만 보내면 잘못 읽은 칸이 그대로 저장되고 세 번 보내 다수결로 합치면 걸러지는 것을 한 표에서 비교하는 데모다.

- 글: [자꾸만 틀리는 LLM을 믿을만하게 만들기](/posts/llm-majority-vote/)
- 데모: `/demos/majority-vote/`

## 재현하는 현상

회차 하나, 배역 둘(래리 머피, 신시아 머피)로 줄였다. 요청 세 개 중 요청 1은 신시아 머피 칸에, 요청 3은 래리 머피 칸에 옆 배역의 배우가 들어갔다(열 밀림). 요청 2는 정답과 같다.

`samples.ts`의 응답은 실제 Gemini 응답이 아니라 글의 오류 유형으로 만든 예시다. 배우는 이모지로 바꿨다.

## 화면

표의 행은 정답, 요청 1~3, 저장되는 값이고 두 모드에서 모양이 같다.

- 한 번만 보내기: 요청 2·3을 흐리게 하고, 요청 1을 그대로 저장되는 값으로 보여준다. 틀린 칸이 빨간 채로 저장된다.
- 세 번 보내 다수결: 요청 세 개를 모두 켜고, 배역마다 2표 이상 받은 배우를 저장되는 값으로 보여준다. 틀린 칸이 요청마다 달라서 틀린 값은 1표에 그친다.

## 다수결 계산

`consensus.ts`는 회전문 `src/service/casting-board/parse.ts`에서 `pickMostCommonValue`와 `buildConsensusPerformances` 중 배역을 합치는 부분을 그대로 옮긴 것이다. 요일, 버전, 확신도처럼 회차의 다른 필드를 합치는 코드는 뺐다.
