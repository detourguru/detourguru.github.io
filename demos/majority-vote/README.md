# 캐스팅 다수결 데모

같은 캐스팅보드를 LLM에 세 번 읽힌 응답을 배역마다 다수결로 합치는 과정을, 확정 기준과 도착한 응답을 바꿔 가며 볼 수 있게 만든 데모다.

- 글: [자꾸만 틀리는 LLM을 믿을만하게 만들기](/posts/llm-majority-vote/)
- 데모: `/demos/majority-vote/`

## 재현하는 현상

회차 하나(래리 머피, 신시아 머피, 재러드, 알라나)를 놓고 응답 세 개에 글에 나온 오류를 하나씩 넣었다. 응답 1에는 정답에 없는 `Unnamed` 배역이 생겼고, 응답 2는 신시아 머피 칸에 래리 머피 배우 `A`가 들어간 열 밀림이고, 응답 3은 `재러드`를 `재럴드`로 읽었다.

세 응답은 `samples.ts`에 적은 예시이고 실제 Gemini 응답이 아니다. 배우 이름은 글처럼 알파벳으로 바꿨다.

## 다수결 계산

`consensus.ts`는 회전문 `src/service/casting-board/parse.ts`에서 두 부분을 그대로 옮긴 것이다. 하나는 `pickMostCommonValue`와 `buildConsensusPerformances` 중 배역을 합치는 부분이고, 다른 하나는 `parseCastingBoardWithConsensus`가 도착한 응답 수에 따라 합치는 방법을 고르는 부분이다. 요일, 버전, 확신도처럼 회차의 다른 필드를 합치는 코드는 뺐다.

도착한 응답이 없으면 실패하고, 하나만 도착하면 다수결 없이 그 응답을 그대로 쓴다. 둘 이상이면 기준을 도착한 응답 수보다 크지 않게 낮춘 뒤, 배역 이름을 키로 같은 배우가 기준 이상 나온 배역만 확정하고 나머지는 `unsureRoles`로 남긴다.

3/3 기준은 실제 서비스에는 없고 글의 비교 실험에서만 썼다. 응답이 둘만 도착하면 3/3을 골라도 기준이 2가 된다.

## 결과 열 표시

결과 열은 정답과 비교해서 아래처럼 표시한다.

| 표시 | 뜻 |
| --- | --- |
| 초록 배우 이름 | 정답과 같은 배우가 확정됐다 |
| 빨간 배우 이름 | 틀린 배우가 확정됐거나 정답에 없는 배역이 확정됐다 |
| 비움 | 정답에 있는 배역인데 기준만큼 표를 얻지 못해 비웠다. 사람이 원본과 대조해서 채워야 한다 |
| 걸러짐 | 정답에 없는 배역이 기준만큼 표를 얻지 못해 확정되지 않았다 |
| 빠짐 | 응답 하나를 그대로 쓸 때 그 응답에 정답 배역이 없다 |
