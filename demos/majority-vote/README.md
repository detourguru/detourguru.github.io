# 캐스팅 다수결 데모

같은 캐스팅보드를 LLM에 여러 번 읽힐 때, 한 번만 보내면 틀린 칸이 그대로 저장되고 세 번 보내 다수결로 합치면 걸러지는 것을 비교하는 데모다.

- 글: [자꾸만 틀리는 LLM을 믿을만하게 만들기](/posts/llm-majority-vote/)
- 데모: `/demos/majority-vote/`

## 재현하는 현상

회차 8개, 배역 4개(래리 머피, 신시아 머피, 재러드, 알라나)인 캐스팅보드에 글에 나온 오류 두 가지를 넣었다.

- 열 밀림: 한 회차를 읽다가 어느 배역 칸부터 왼쪽 배역의 배우가 한 칸씩 밀려 들어온다
- 유령 배역: 표에 없는 `Unnamed` 배역이 생긴다

`samples.ts`의 응답은 실제 Gemini 응답이 아니라 예시다. 틀린 칸 수만 글의 측정값에 맞췄다.

- 한 번만 보내기: 요청 10번, 틀린 칸 6, 0, 2, 2, 0, 0, 2, 7, 0, 4 (평균 2.3칸, 정답과 같은 요청 4번)
- 세 번 보내 다수결: 시행 5번, 요청별 틀린 칸 0·3·2, 0·0·2, 2·4·5, 0·5·0, 0·5·2 (평균 2.0칸). 다수결 뒤 0, 0, 2, 0, 0 (평균 0.4칸)

다수결 뒤에도 틀리는 3번째 시행은 두 응답이 같은 회차를 같은 모양으로 밀려 읽게 만들었다. 회차와 배우, 어느 칸이 어떻게 틀렸는지는 모두 예시다. 배우 이름은 글처럼 알파벳으로 바꿨다.

## 다수결 계산

`consensus.ts`는 회전문 `src/service/casting-board/parse.ts`에서 `pickMostCommonValue`와 `buildConsensusPerformances` 중 배역을 합치는 부분을 그대로 옮긴 것이다. 요일, 버전, 확신도처럼 회차의 다른 필드를 합치는 코드는 뺐다. 데모는 회차마다 세 응답을 2표 기준으로 합친다.

## 화면 읽는 법

- 위쪽 작은 지도는 응답 하나를 회차(행) × 배역 4칸과 그 외 배역 1칸(열)으로 줄인 것이다. 빨간 점이 정답과 다른 칸이다.
- 표의 빨간 칸은 그 방법으로 저장되는 값이 틀린 칸이고, 아래에 정답을 적었다.
- 다수결 표에서 초록 글씨가 붙은 칸은 한 응답이 다르게 읽었지만 다수결로 걸러진 칸이다. 몇 번째 응답이 어떤 값으로 읽었는지 함께 적었다.
