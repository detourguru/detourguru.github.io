# 놓친 메시지 다시 받기 데모

소켓이 끊겼다가 다시 연결할 때 마지막으로 받은 메시지의 저장 시각을 기준으로 놓친 메시지를 묻는데, `$gt`로 물으면 같은 밀리초에 저장된 메시지가 채팅에서 빠지고 `$gte`로 묻고 id로 거르면 빠지지 않는 것을 두 채팅 화면에 같은 소켓 흐름을 흘려 비교하는 데모다.

- 글: [백그라운드에서 돌아오면 놓친 메시지는 어디서 받을까?](/posts/socket-catchup/)
- 데모: `/demos/socket-catchup/`

## 재현하는 현상

한 플레이어에게 메시지 네 개가 저장된다. 그중 플레이어 A의 "고블린 나왔어요"와 플레이어 B의 "같이 잡아요"는 둘 다 12:00:05.348에 저장된다. 앱은 "고블린 나왔어요"까지 소켓으로 받아 채팅에 넣고 소켓이 끊긴다. 그 뒤 "같이 잡아요"와 "잡았다"는 서버에 저장만 된다. 다시 연결하면 "고블린 나왔어요"를 기준으로 놓친 메시지를 묶음으로 받는다.

- 왼쪽 $gt로 묻기: 05.348보다 뒤에 저장된 "잡았다"만 묶음에 담겨서 "같이 잡아요"가 채팅에서 빠진다.
- 오른쪽 $gte로 묻고 id로 거르기: 05.348에 저장된 두 메시지도 묶음에 담긴다. 이미 있던 "고블린 나왔어요"는 id로 걸러지고 빠진 메시지가 없다.

화면은 위의 설명 문장, 두 채팅, 재생 버튼이다. 처음 화면은 재생이 끝난 결과이고 설명 문장도 결과를 말한다. 재생을 누르면 연결, 메시지 수신, 끊김, 다시 연결, 묶음 수신이 두 화면에 똑같이 일어나고, 설명 문장이 단계마다 지금 일어난 일로 바뀐다. 끊긴 동안 서버에 저장만 되는 메시지는 화면에 따로 그리지 않고 끊김 단계의 설명과 조금 더 기다리는 것으로 보여준다. 동작 줄이기 설정이 켜져 있으면 재생 대신 바로 결과를 보여준다.

## 옮긴 코드와 뺀 것

`catchup.ts`의 `queryCatchup`은 몽글 백엔드의 캐치업 쿼리에서 기준 메시지의 저장 시각을 찾아 `timestamp`를 비교하는 조건만 옮긴 것이다. `reconnect`의 거르기는 프론트 `useChatStore.addChats`에서 들고 있는 id를 거르는 부분이다. `timeline.ts`는 소켓 흐름의 순서다.

뺀 것은 다음과 같다.

- 최신 기준 30개 제한과 `hasMore`. 메시지가 네 개뿐이라 결과가 같다.
- 시각이 같을 때 `_id`로 정렬하는 부분. 묶음에 담기는 메시지는 바뀌지 않는다.
- 메시지 종류별 처리기와 수신 큐. 데모의 메시지는 모두 플레이어 채팅이고 받으면 바로 채팅에 넣는다.
- 백그라운드 1분 타이머. 데모에서는 끊김이 바로 일어난다.

## 알아둘 점

메시지 내용과 시각은 글의 예시로 만든 값이다. 몽글 백엔드 쿼리는 `$gt`이고 `$gte`는 글에서 대안으로 다룬 조건이다. 실제로는 소켓이 끊기는 순간과 같은 밀리초에 다른 메시지가 저장될 때만 생기는 일이라, 데모는 그 순간을 골라서 보여준다.
