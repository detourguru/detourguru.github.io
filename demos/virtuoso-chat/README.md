# 채팅 바닥 고정 데모

[English](README.en.md)

react-virtuoso 채팅에서 새 메시지가 바닥에 붙지 않거나 가만히 있어도 스크롤이 흔들리는 현상을 재현하고, 고친 뒤와 바꿔 가며 볼 수 있게 만든 데모다.

- 글: [가상 스크롤을 고치려고 가상화를 껐다](/posts/virtuoso-chat-bottom/)
- 데모: `/demos/virtuoso-chat/`

## 재현하는 현상

첫 번째는 바닥 미달이다. `followOutput`은 아직 재지 않은 메시지의 높이를 추정값으로 계산해서 스크롤을 끝낸다. 그런데 이미지가 늦게 로드되거나 선택지 버튼이 늦게 붙으면 스크롤이 끝난 뒤에 메시지가 커지고, 그만큼 바닥에서 떨어진 채 멈추게 된다.

두 번째는 흔들림이다. 화면 밖으로 나갔던 메시지가 다시 그려지면 virtuoso가 높이를 새로 잰다. 이 데모에서는 등장 애니메이션이 높이를 바꾸는데 다시 그려질 때마다 처음부터 재생되니까, 새로 잰 높이가 기억해 둔 높이와 달라져서 가만히 있는 화면이 움직인다.

## 고친 방법

고친 뒤는 글에 나온 우회책 1, 2, 3번을 함께 켠 상태다. 화면의 스위치가 `VirtuosoList`의 `fixed`와 `MessageItem`의 `fixedHeight`를 바꾼다.

| | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| 1. 높이 미리 확정 (`MessageItem.tsx`) | 이미지는 로드 문구 한 줄에서 200px로 커지고 선택지는 500ms 뒤에 붙는다. 등장 애니메이션 `enter-grow`는 높이를 바꾸면서 마운트될 때마다 재생된다 | 이미지와 선택지 자리를 처음부터 잡아 둔다. 등장 애니메이션 `enter-fade`는 `transform`과 `opacity`만 쓰고 메시지 id마다 한 번만 재생된다 |
| 2. 바닥 근처 언마운트 막기 (`VirtuosoList.tsx`) | `increaseViewportBy` 0, 메시지 전부 | `increaseViewportBy={{ top: 12000, bottom: 1200 }}`, 최근 30개만 |
| 3. 직접 바닥에 붙이기 (`useStickToBottom.ts`) | `followOutput="auto"` | `followOutput`을 끄고 `totalListHeightChanged`가 오면 다음 프레임에 실제 `scrollHeight`로 내린다 |

애니메이션 재생 기록과 이미지 로드 기록은 컴포넌트 상태에 두면 가상화가 언마운트할 때 같이 사라지기 때문에 `mountRegistry.ts`에 따로 뒀다.

2번은 메시지 수와 최대 높이를 곱한 값이 `increaseViewportBy.top`보다 작아야 성립한다. 30개에 320px이면 9600px이고 top은 12000px이다. 이 조건이 깨지면 바닥 근처가 다시 언마운트되니까 모듈을 불러올 때 에러를 던지게 작업했다.

3번은 바닥 거리만 보고 고정을 풀면 메시지가 빠르게 쌓이는 중에 바닥이 아니라고 잘못 판단할 수 있다. 그래서 최근 300ms 안에 휠이나 터치, 키 입력이 있었을 때만 사용자가 직접 올린 것으로 보고 고정을 푼다. 바닥에서 1px 안으로 돌아오면 다시 고정한다.

## 현상을 잡아내는 기준

측정은 `metrics.ts`가 매 프레임 하고 화면 숫자는 100ms마다 한 번 바꾼다.

바닥 미달은 바닥에서 2px 안이면 바닥으로 본다. 사용자가 바닥을 떠나지 않았는데 메시지가 추가되면 1초 뒤에 확인하고, 그때도 바닥이 아니면 150ms를 더 지켜본다. 한두 프레임 늦게 따라붙는 경우까지 미달로 세지 않으려고 이 150ms 동안 한 번도 바닥에 닿지 않아야 1회로 센다.

흔들림은 스크롤 영역 가운데 있는 메시지가 지난 프레임보다 얼마나 움직였는지 더한 값이다. 사용자가 방금 움직였거나 메시지가 자라는 중이면 흔들림이 아니니까, 최근 300ms 안에 입력이 있었거나 추가 뒤 1초가 안 지났으면 빼고 잰다. 연달아 움직인 프레임은 한 번으로 묶고 합이 4px 이상일 때만 알린다.

원인 문장은 `rowWatch.ts`가 만든다. 행마다 높이 변화와 재마운트를 4초 동안 기록해 두고, 문제가 감지되면 그 사이 높이가 가장 크게 바뀐 행을 원인으로 적는다. 예를 들어 `사진을 보냈습니다` 메시지가 다시 그려지면서 16px에서 258px로 바뀌었다면 그 메시지를 적는 식이다. 가장 크게 바뀐 행을 고르는 방식이라 원인을 증명하는 건 아니다.

자동으로 보기(`useScenario.ts`)는 늦게 커지는 메시지 5개를 1.3초 간격으로 보내고, 10개를 50ms 간격으로 한꺼번에 보낸 뒤 위로 올렸다 내리고 2.5초를 지켜본다.

따라 하기(`useTutorial.ts`)는 실제로 감지됐을 때만 다음 단계로 넘어간다. 마지막 단계는 고친 뒤에서 6번 이상 보내고 한 번 이상 오르내린 다음 1.5초 동안 아무것도 감지되지 않아야 끝난다. 미달 확인이 추가 1초 뒤에 끝나기 때문에 그만큼 기다리게 했다.

| `src/App.tsx` | 화면, 스위치, 보내기 버튼과 자동으로 보기, 따라 하기 연결 |
| `src/lists/VirtuosoList.tsx` | Virtuoso 설정. `fixed`에 따라 2번과 3번을 켠다 |

| `src/MessageItem.tsx` | 메시지 행. 늦게 커지는 이미지와 선택지, 등장 애니메이션 |
| `src/mountRegistry.ts` | 재마운트 뒤에도 남아야 하는 재생 기록과 이미지 로드 기록 |
| `src/messages.ts` | 메시지 종류와 시드를 고정한 초기 메시지 60개, 언어별 메시지 문장 |
| `src/text.ts` | 화면 문구. 주소에 `?lang=en`이 있으면 영어 문구를 쓴다 |
| `src/useMessageFeed.ts` | 메시지 추가와 스트리밍, 연속 추가 |
| `src/metrics.ts` | 바닥 미달과 흔들림 측정 |
| `src/rowWatch.ts` | 행별 높이 변화와 재마운트 기록, 원인 문장 |
| `src/useScenario.ts` | 자동으로 보기 |
| `src/useTutorial.ts` | 따라 하기 단계와 안내 문구 |

| `src/styles.css` | virtuoso는 margin을 재지 못해서 행 간격을 padding으로 준다 |

## 알아둘 점

이미지 로드는 타이머로 흉내 낸 것이다. 처음 로드는 300ms에서 900ms 사이, 다시 그려질 때는 40ms에서 120ms 사이로 무작위라서 실행마다 미달 횟수와 흔들림 크기가 조금씩 다르다. 초기 메시지 60개는 시드를 고정해서 매번 같다.

흔들림은 화면 가운데 메시지 하나의 위치로 잰다. 고친 뒤는 최근 30개만 남기는데, 이 데모에는 과거 기록을 위로 불러오는 기능이 없어서 쓸 수 있는 방식이다. 개발 모드의 이중 마운트가 재마운트 측정에 섞이기 때문에 StrictMode는 쓰지 않는다.

영문 글의 쇼트코드는 데모 주소에 `?lang=en`을 붙인다. 영어는 시드가 같아서 메시지 종류와 순서는 한국어와 같지만 문장 길이가 달라서, 행 높이와 측정값은 한국어와 다르게 나올 수 있다.

글의 4번(바닥만 비가상)과 Virtuoso Message List, TanStack Virtual 전환은 이 데모에 넣지 않았다.
