# 맵 에디터 카드와 화살표 데모

격자 위 장소 카드를 이웃끼리 화살표로 잇는 맵 에디터에서 겪은 문제 세 가지를, 고치기 전과 고친 뒤로 바꿔 가며 볼 수 있게 만든 데모다.

- 글: [맵 에디터의 카드와 화살표를 하나의 데이터로 그리기까지](/posts/map-editor-nodes-and-edges/)
- 데모: `/demos/map-editor/`

## 재현하는 현상

첫 번째는 화면을 옮기면 화살표가 카드에서 떨어지는 현상이다. 처음에는 카드를 CSS grid에 놓고 화살표는 카드의 화면 위치를 재서 따로 그렸다. 그런데 확대와 이동은 카드가 들어 있는 영역에만 걸리고 화살표는 그 밖에 있으니까, 화면을 옮기면 카드만 움직이고 화살표는 예전 자리에 남는다.

두 번째는 카드를 옮겨도 예전 이웃 화살표가 남는 현상이다. 이웃을 서버에 저장된 이웃과 화면에서 계산한 이웃을 합쳐서 만들었는데, 저장된 이웃은 처음 좌표 그대로라 카드를 옮겨도 바뀌지 않는다. 그래서 광장을 두 칸 아래로 옮기면 이제 이웃이 아닌 우물과 시장으로 가는 화살표가 그대로 남는다.

세 번째는 다른 지역 장소가 섞이면서 화살표가 잘못 생기는 현상이다. 화면에 그릴 장소 목록을 게임 전체 장소와 지금 지역의 이웃 목록, 두 응답으로 만드는데 두 목록을 그냥 이어붙이면 이 지역 장소가 두 번 들어간다. 또 출구로 이어진 숲 지역 장소가 숲 기준 이웃 좌표를 들고 와서 마을 지도의 카드와 엉뚱하게 이어진다.

## 고친 방법

| 현상 | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| 화면 이동 | `PanScreens.tsx`의 `DomArrowScreen`. grid 카드에만 `transform`을 걸고 SVG 화살표는 처음 한 번 잰 좌표로 그린다. react-xarrows에서 `updateXarrow`를 부르지 않은 상태와 같다 | `FlowPanScreen`. 장소 목록 하나로 React Flow 노드와 엣지를 같이 만들어서(`flow.ts`의 `buildFlow`) 확대와 이동이 둘에 한 번에 걸린다 |
| 카드 옮기기 | `MoveScreen.tsx`의 `toLocations`. 저장된 이웃을 앞에, 화면에서 계산한 이웃을 뒤에 두고 좌표 키로 합치니까 같은 칸이면 저장값이 남는다 | 옮길 때마다 지금 좌표로 이웃을 다시 계산한다. 이웃 판정을 서버에 맡긴 구조를 흉내 낸 것이다 |
| 다른 지역 | `AreaScreen.tsx`의 `mergeLocations('before')`. 이 지역 장소와 이웃으로 등장한 장소를 이어붙인다 | 두 id 목록을 `Set`으로 합치고 다른 지역 장소는 이웃 목록을 비운다. 출구 화살표는 이 지역 장소 쪽에서 그려지니까 그대로 남는다 |

카드 테두리 8곳에는 보이지 않는 핸들을 달고, 두 카드의 좌표 차이로 나가는 핸들과 들어오는 핸들을 고른다(`grid.ts`의 `getAnchorCoordinates`). 출구 화살표는 점선으로 양방향으로 그린다.

화면 이동의 두 화면은 같은 크기에서 같은 변환을 쓴다. 화면 옮기기 버튼은 가운데를 기준으로 1.15배 확대하고 오른쪽 아래로 가로 8%, 세로 4%만큼 민다(`grid.ts`의 `movedTransform`).

## 현상을 잡아내는 기준

화면 이동은 이동이 끝난 다음 프레임에 화살표 하나를 골라, 화살표 시작점과 그 화살표가 붙은 카드 핸들 사이 거리를 화면 좌표로 잰다. React Flow 쪽은 엣지 path의 시작점을 `getScreenCTM`으로 화면 좌표로 바꿔서 잰다. 핸들 크기만큼의 오차는 넘기려고 3px보다 멀 때만 떨어졌다고 본다.

카드 옮기기는 가로와 세로, 대각선 중 가장 먼 칸 수가 1보다 큰 장소로 가는 화살표를 `bogus`로 표시하고(`buildFlow`의 `markFar`), 그 장소 이름을 알림에 띄운다. 광장을 제자리로 돌려놓았을 때는 판정하지 않는다.

다른 지역은 다른 지역 장소에서 나온 일반 화살표를 `bogus`로 센다(`buildFlow`의 `currentAreaId`). 같은 id 노드를 React Flow에 두 번 넘기면 중복 key 경고가 나기 때문에 노드는 한 번만 넘기고 중복 개수만 센다. 상대 카드가 없는 화살표는 그릴 수 없으니 세지 않는다.

따라 하기(`tutorial.ts`)는 현상마다 고치기 전과 고친 뒤 두 단계씩, 모두 6단계다. 고치기 전은 현상이 실제로 보여야 끝나고, 고친 뒤는 고치기 전에서 현상을 본 다음 같은 행동을 했을 때 현상이 없어야 끝난다.

## 알아둘 점

고치기 전 화면 이동은 react-xarrows와 react-zoom-pan-pinch 대신 같은 구조를 직접 만들어서 보여 준다. 거리는 화살표 하나로만 재서 화면 크기에 따라 떨어진 정도가 달라진다.

서버는 메모리 데이터로 흉내 냈고 막힌 길(`isActivated`)은 데이터에 넣지 않았다. 카드 옮기기의 판정은 1칸보다 먼 화살표만 센다.

다른 지역 데이터는 숲 장소 좌표가 마을의 시장과 성문 칸에 겹치도록 일부러 배치했다. 겹치는 칸이 달라지면 잘못 생기는 화살표 수도 달라진다.
