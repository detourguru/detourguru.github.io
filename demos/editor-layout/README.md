# 에디터 레이아웃 데모

에디터 화면이 시기마다 어떤 틀이었는지를 와이어프레임 네 장으로 바꿔 가며 보는 데모다. 각 와이어프레임에서 메뉴나 버튼을 눌러, 한 번에 무엇이 보이고 무엇이 바뀌는지 직접 확인할 수 있다.

- 글: 아직 없음
- 데모: `/demos/editor-layout/`

## 재현하는 현상

| 스위치 | 시기 | 옮겨 그린 코드 | 누르면 |
| --- | --- | --- | --- |
| 단계별 진행 | 2025년 3월 | 초기 커밋의 `EditorLayout.tsx`(진행 막대와 이전, 다음 버튼, `<Outlet />` 카드 한 장), 단계 화면 `CreateGame.tsx`, `CreatePlayer.tsx`, `CreateMap.tsx` | 이전과 다음으로 단계가 바뀌고 카드 내용이 통째로 바뀐다. 마지막 단계 버튼은 `완료`다 |
| 메뉴와 카드 | 2025년 9월 | 패널 레이아웃으로 바꾸기 직전의 `EditorLayout.tsx`, `SideNav.tsx`, `DatabaseNav.tsx`, `gnb.ts`. 위쪽 탭, 왼쪽 메뉴, 제목바, 카드 한 장 | 탭을 바꾸면 그 묶음의 첫 메뉴가 열린다. 메뉴를 누르면 제목과 카드가 바뀐다. 캔버스에서는 저장하기 버튼이 없다 |
| 패널 | 2025년 10월부터 | `PanelEditorLayout.tsx`. 액티비티 바, 메뉴, 캔버스, 에셋 목록, 속성 패널 | 메뉴나 캔버스의 항목을 누르면 속성 패널만 바뀐다. 에셋 목록의 탭을 누르면 타일 수만 바뀐다 |
| 모바일 | 2026년 1월부터 | 지금 모바일 에디터 화면 | 설정 버튼을 누르면 설정 목록이 화면을 덮는다 |

## 옮긴 것과 바꾼 것

- 화면을 나누는 틀, 영역 수, 누르면 바뀌는 범위는 그 시기 코드 그대로다.
- 메뉴, 탭, 카드, 항목 이름은 도메인 말을 빼고 일반적인 말로 바꿨다. 탭과 메뉴 개수도 줄였다.
- 단계별 진행의 앞 두 단계는 실제 화면처럼 왼쪽 기본 설정 카드(이름, 분류나 유형, 설명)와 오른쪽 작은 카드들로 그렸다. 오른쪽 카드 이름도 일반적인 말로 바꿨다.
- 실제 진행 막대에는 마지막에 미리 보기 단계가 하나 더 있었지만, 초기 커밋에서 라우트가 주석 처리돼 화면이 없었다. 그래서 데모에서는 뺐다.
- 폼 내용과 에셋 타일은 회색 막대와 빈 상자로 그렸다.
- 패널과 모바일은 지금 화면을 기준으로 그렸다. 패널에 액티비티 바가 붙은 건 2025년 11월이고, 아래쪽 조건 경로 패널은 뺐다. 액티비티 바 아이콘은 실제 여섯 개 대신 lucide(ISC)의 play, rocket, sparkles 세 개를 옮겨 그렸다. 모바일 오른쪽 위 아이콘도 lucide의 map, eye다.
- 모바일은 AI 버튼, 랜덤과 자동생성 버튼을 뺐다.

## 색과 모서리

색은 제품 색과 관계없이 정한 청록 계열 하나를 모든 단계에 똑같이 입혔다. 블로그가 어두운 모드면 어두운 값을 쓴다. 와이어프레임 CSS는 색과 모서리를 `.wire`의 `--w-*` 변수로만 읽는다. 데모 규칙은 색을 `shared/base.css` 토큰만 쓰라고 하지만, 와이어프레임 안쪽을 실제 앱 화면처럼 보이게 하려고 예외로 따로 색을 정했다.

실제로는 시기마다 색이 달랐다. 이 데모는 레이아웃만 비교하려고 색을 하나로 맞췄다.

## 알아둘 점

- 와이어프레임은 너비 520px 이하에서 4:3, 그 위에서 16:10이다. 글자 크기는 틀 너비에 맞춰 9px에서 13px 사이로 바뀐다.
- 저장하기, 저장, 미리보기, 게시하기 같은 버튼은 그림이고 눌리지 않는다.
